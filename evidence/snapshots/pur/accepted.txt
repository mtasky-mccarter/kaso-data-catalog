10. QUANTITY CONTRACT
============================================================

Source-confirmed canonical line formulas:

remaining_qty =
    POCET - P_DEL - P_PRIJ - P_PL

processed_qty =
    P_DEL + P_PRIJ + P_PL

Meanings:

POCET
= ordered/source document quantity

P_DEL
= cancelled/reduced quantity bucket

P_PL
= quantity transferred/covered by downstream transport-list lifecycle

P_PRIJ
= stored receipt/fulfilment bucket used by OBJD lifecycle logic

Do NOT interpret P_PL as received quantity.

Do NOT interpret P_DEL automatically as a physical supplier non-delivery
reason without separate evidence.

12. FULFILMENT STATE CONTRACT - CRITICAL
============================================================

Canonical current fulfilment state:

D_OBJD_L.GetS_STAV(OBJD_L.FLAGS_S)

Source-confirmed raw state slot:
FLAGS_S position / Flag 11

Values:

0 = Nevybavené
1 = Odoslané
2 = Vybavené z časti
3 = Vybavené
4 = Potvrdené dodanie

This is a CRITICAL semantic correction.

OBJD_L.STAV is NOT the authoritative fulfilment state.

Raw STAV codes include:

000-38 = Otvorená
000-40 = Uzavretá
000-41 = Vybavená z časti
000-42 = Vybavená
POTVRD-DOD-4011 = Potvrdené dodanie

But these raw document-state values are not safely equivalent to the
business fulfilment state.

Live MC state cross-check proved examples including:

Flag11=0 Nevybavená + STAV='000-40' Uzavretá
Flag11=3 Vybavená   + STAV='000-38' Otvorená

Specifically, the snapshot included:
40 supplier orders with STAV='000-40' while Flag11=0.

Therefore DO NOT ASSUME:

STAV='000-40'
= fulfilled order

For business fulfilment state use:
D_OBJD_L.GetS_STAV(FLAGS_S)
