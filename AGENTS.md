# KASO Data Catalog — engineering rules

**REPOSITORY STATE IS MEMORY. THE HANDOFF IS A DELTA CONTRACT. THE CHAT PROMPT IS ONLY A COMMAND.**

- `main` is canonical. Generated publications are derived; canonical YAML/SQL is authoritative.
- Follow [Codex Lean Execution v4](docs/codex-execution-standard-v4.md). Historical v3 handoffs remain provenance, not instructions to replay unchanged semantics.
- Start with this file, the nearest short domain `AGENTS.md`, and `python tools/check_codex_handoff.py <handoff> --plan`. Use the validated compact plan as context; do not load the full handoff when the plan suffices.
- Map only approved evidence. Do not invent Oracle objects, meanings, JOINs, writer roles or temporal behavior. MC is authoritative; other owners require separate validation. Comments are technical clues; grants are access capability; dependencies are not runtime proof. Read [Mapping Standard](docs/mapping-standard.md) only for semantic-rule changes or a specific conflict.
- Preserve Oracle names, stable IDs, leading-zero codes, nulls, uncertainty/status and temporal distinctions. Never upgrade class-E-only evidence into confirmed facts. Keep raw evidence checksums and retained snapshots traceable.
- After plan validation, no broad searches, unrelated domains, raw Oracle rediscovery, manual registry rereads or recounting tested invariants. Retrieve only the smallest failing/missing/conflicting record or range. Stop rather than guess if the approved delta cannot be represented losslessly.
- Prefer checksummed structured inputs and deterministic materializers. Supply semantic records once; do not duplicate them in chat, handoff prose and generator code.
- Diagnostics are read-only SELECTs. No production DML/DDL or data-changing PL/SQL. SQL Navigator 5.5.4.847 is the client; do not infer Oracle server version.
- Use `python tools/plan_change_validation.py --base origin/main --head HEAD`. Run parser checks, affected domain/SQL/publication tests and reference/evidence summaries first. Once the diff is stable, run the catalog validator, full unittest suite and required publication check once. Repeat only after changes that invalidate results.
- Keep successful output to command, status, counts and summary. Save large logs locally. Inspect changed filenames/stat before individual patches. Never stream full successful logs, large YAML/source/dependency dumps or generated document text into model context.
- Every approved mapped-domain closure includes DOCX/PDF/manifest, unless explicit user-approved deferral is recorded canonically. Missing or stale publication means delivery is incomplete. Follow [Publication Standard](docs/publication-standard.md).
- Every new canonical revision records change classification and publication impact. Contract and documentation versions are separate approved values. Publication-visible changes advance documentation version and regenerate the family in the same PR. Preserve all previous versioned artifacts; never edit generated files as source.
- New handoffs use [v2 template](docs/handoffs/codex-handoff-v2.template.yaml). Keep historical handoffs/revisions unchanged. Put contracts under `catalog/`, evidence manifests under `evidence/manifests/`, retained evidence under `evidence/snapshots/`, diagnostics under `sql/diagnostic/`, publications under `generated/<slug>/`.
- Work on a feature branch and deliver a focused PR with green CI. Merge only when authorized, then verify `main` CI. A validated committed milestone is a context boundary: use a fresh task for the next substantial phase and carry continuity through repository state.
